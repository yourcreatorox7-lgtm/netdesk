# معماری NetDesk

```
┌────────────────────── رابط کاربری (React + TypeScript، RTL) ──────────────────────┐
│ خانه │ پروفایل‌ها │ دستیار │ آموزش‌ها │ ابزارهای شبکه │ هسته و ابزارها │ تنظیمات │
└──────────────────────────────┬──────────────────────────────────────────────────┘
                               │ IPC (invoke) — فقط فرمان‌های فهرست‌شده در capabilities
┌──────────────────────────────▼──────────────── src-tauri (Rust) ─────────────────┐
│ commands.rs   تبدیل JSON، spawn_blocking، اعتبارسنجی ورودی                       │
│ secrets.rs    keyring سیستم‌عامل — UI فقط می‌نویسد/می‌پرسد/حذف می‌کند، نمی‌خواند    │
│ store.rs      profiles.json / servers.json / history.json (بدون رمز، نوشتن اتمیک)│
│ tools.rs      اجرای ابزار خارجی: هش سنجاق‌شده، تأیید صریح، UAC، توقف هنگام خروج  │
│ ssh سیستم (BatchMode، کلید)   mstsc / open / xfreerdp برای RDP                     │
└──────────────────────────────┬──────────────────────────────────────────────────┘
┌──────────────────────────────▼──────── crates/netcore (فقط کتابخانه‌ی استاندارد) ──┐
│ dns probe stats config proxy server rdp report singbox tools sha256 json b64      │
└──────────────────────────────────────────────────────────────────────────────────┘
```

## چرا Tauri 2 و نه Electron
- باینری ۵ تا ۱۵ مگابایت به‌جای ۱۰۰+؛ مصرف RAM کمتر.
- مدل «capabilities» دسترسی هر پنجره را صریحاً محدود می‌کند.
- منطق شبکه در Rust، بدون نیاز به Node در زمان اجرا.

## چرا netcore بدون وابستگی است
هر crate خارجی سطح حمله و ریسک زنجیره‌ی تأمین است. DNS، TCP، SOCKS5، JSON و Base64 در حد نیاز این برنامه کوچک‌اند و با ۲۵ تست پوشش داده شده‌اند. نتیجه: `cargo test` کاملاً آفلاین اجرا می‌شود.

## سه حالت و مرزهایشان

| حالت | نیازمندی | ماژول‌ها | برچسب UI |
|---|---|---|---|
| رایگان — محلی | هیچ | probe، stats، config، proxy | ● محلی و رایگان |
| رایگان — سرور عمومی | اینترنت، بدون حساب | dns (resolverهای عمومی)، report | ○ سرور عمومی، بدون حساب |
| VPS و RDP | سرور و کلید/حساب کاربر | server، rdp | ◆ نیازمند سرور یا حساب شما |
| پیشرفته — پرخطر | برنامه‌ی خارجی که خود کاربر نصب کرده | tools، singbox، sha256 | نشان ریسک: متوسط / پرخطر / بحرانی |

RDP هیچ وابستگی به پروفایل‌ها یا پروکسی ندارد (الزام بخش ۲). برنامه هیچ‌جا «اتصال رایگان» تبلیغ نمی‌کند (الزام بخش ۱).

## تصمیم‌های امنیتی
1. **رمزها فقط در keyring.** متن کامل لینک (که UUID/رمز دارد) با کلید `profile:<fingerprint>` ذخیره می‌شود. JSONها فقط فراداده دارند.
2. **پشتیبان بدون رمز.** فایل پشتیبان `containsSecrets: false` دارد. خروجی «کامل» فقط با درخواست صریح کاربر و با هشدار.
3. **SSH فقط با کلید**، `StrictHostKeyChecking=accept-new` (TOFU)، `--` قبل از مقصد و رد نام‌های شروع‌شده با «-» (جلوگیری از تزریق گزینه).
4. **RDP بدون رمز در فایل**؛ رد مقادیر حاوی خط جدید (تزریق تنظیمات .rdp)؛ NLA فعال.
5. **پروکسی HTTP:** رد CR/LF در نام مقصد (تزریق هدر).
6. **تجزیه‌گرها سقف دارند:** ورودی ۴MB، ۲۰٬۰۰۰ خط، عمق JSON ۳۲، خط ۶۴KB.
7. **خود NetDesk هیچ رهگیری TLS، نصب CA، تزریق بسته یا دسترسی مدیر ندارد.** ابزارهای خارجی‌ای که این کارها را می‌کنند فقط از بخش «ابزارهای پرخطر» و با قواعد بخش بعد اجرا می‌شوند.
8. **CSP سخت‌گیرانه** در tauri.conf.json؛ بدون بارگذاری منبع خارجی (فونت Vazirmatn داخل بسته است).

## ابزارهای خارجی پرخطر (`tools.rs` و `netcore::tools`)

سورس ابزارها برای راحتی ساخت، در `vendor/` با لایسنس خودشان کپی شده است (جزئیات در `vendor/README.md`). این کدها **داخل NetDesk لینک یا بسته‌بندی نمی‌شوند** و ممیزی هم نشده‌اند. کاربر آن‌ها را با `scripts/build-tool.ps1` می‌سازد و NetDesk فایل ساخته‌شده را به‌صورت پردازه‌ی جدا اجرا می‌کند. همه‌ی این قواعد در Rust اجرا می‌شوند:

1. فقط شناسه‌های فهرست ثابت `netcore::tools::catalog()` قابل اجرا هستند: sing-box، Xray، MasterHttpRelayVPN، mhr-cfw، FlowDriver و سه پروژه‌ی SNI Spoofing.
2. **هش SHA-256** فایل اجرایی هنگام تنظیم سنجاق و پیش از هر اجرا دوباره محاسبه می‌شود. اگر فایل عوض شود، تأیید باطل و اجرا متوقف می‌شود.
3. **تأیید چندمرحله‌ای:** دروازه‌ی صفحه، تیک تک‌تک هشدارها، تایپ عبارت تأیید وابسته به سطح ریسک، و پنجره‌ی تأیید نهایی پیش از اجرای ابزار. تغییر مسیر یا آرگومان، یا بالا رفتن `CONSENT_VERSION`، تأیید را باطل می‌کند. «پیدا کردن خودکار» فقط فیلدها را پر می‌کند.
4. **بدون shell:** آرگومان‌ها با `split_args` جدا و مستقیم به پردازه داده می‌شوند.
5. **دسترسی مدیر فقط با UAC/pkexec:** NetDesk خودش ارتقا نمی‌گیرد. پردازه‌ی ارتقایافته از کنترل NetDesk خارج است.
6. خروجی هر ابزار در `logs/<id>.log` است. پردازه‌های فرزند هنگام بستن برنامه بسته می‌شوند.
7. برای ابزارهایی که CA نصب می‌کنند، روش حذف گواهی در هشدارها و آموزش آمده است.

پیش‌فرض `LISTEN_HOST` دو پروژه‌ی SNI در سورسشان `0.0.0.0` است؛ آموزش‌ها آن را به `127.0.0.1` تغییر می‌دهند.

### اتصال با sing-box
`netcore::singbox` از پروفایل (vless با TLS/Reality/uTLS و ترابری ws/grpc/http/httpupgrade، vmess، trojan، ss، hysteria2، tuic، socks، http) کانفیگ می‌سازد. ورودی `mixed` فقط روی `127.0.0.1` است. پیش از اجرا، آزاد بودن پورت بررسی می‌شود تا تست به پروکسی برنامه‌ی دیگری نرسد. کانفیگ (که رمز دارد) پس از باز شدن پورت پاک می‌شود.

**تست سلامت انتها-به-انتها:** از داخل تونل یک `GET http://www.gstatic.com/generate_204` فرستاده می‌شود و پاسخ واقعی لازم است. پاسخ موفق SOCKS CONNECT کافی نیست.

## اتصال خودکار (`auto.rs`)
1. سنجش موازی TCP همه‌ی پروفایل‌ها (hysteria2 و tuic که UDP هستند در انتهای فهرست).
2. تست واقعی حداکثر ۱۰ نامزد، تا ۳ موفق. برای TLS روی TCP، در صورت شکست: `record_fragment` و سپس `fragment`.
3. کم‌تأخیرترین انتخاب و در صورت تنظیم، پروکسی سیستم روشن می‌شود.
4. **پایشگر:** هر ۲۰ ثانیه سلامت؛ پس از ۳ خطای پیاپی (یا بسته شدن هسته) جابه‌جایی. اگر هیچ‌کدام کار نکرد، پروکسی سیستم برمی‌گردد تا اینترنت کاربر قطع نماند. پس در این حالت ترافیک مستقیم می‌شود (kill switch نیست).
5. هر اتصال یا قطع، «نسل» را بالا می‌برد و کارهای قدیمی خودشان متوقف می‌شوند.

### پروکسی سیستم (`sysproxy.rs`)
فقط `HKCU` (بدون دسترسی مدیر). مقدار قبلی پیش از تغییر روی دیسک ذخیره و هنگام قطع، خروج یا اجرای بعدی (پس از کرش) برگردانده می‌شود. اگر برنامه‌ی دیگری پروکسی را عوض کرده باشد، دست نمی‌خورد.

### اشتراک‌ها
فقط `https` (از جمله پس از ریدایرکت)، سقف ۲MB و ۳۰ ثانیه. نشانی در keyring می‌ماند و از stdin به `curl` داده می‌شود تا در فهرست پردازه‌ها دیده نشود. رابط کاربری فقط نام میزبان را می‌بیند.

## دستیار هوش مصنوعی (`ai.rs`)
- فقط Ollama روی `127.0.0.1`؛ `netcore::localhttp` هر آدرس غیر loopback را رد می‌کند.
- مدل نام، نشانی، رمز، UUID و لینک اشتراک را نمی‌بیند.
- خروجی مدل با JSON schema محدود است و کار پیشنهادی دوباره در Rust با فهرست مجاز تطبیق داده می‌شود. هیچ کاری برای اجرای فرمان، ابزار پرخطر یا تأیید هشدار وجود ندارد.
- «خلبان خودکار» پیش‌فرض خاموش است و حداکثر ۳ قدم دارد.

## نقشه‌ی راه (آنچه هنوز نیست)
- **حالت TUN** برای عبور همه‌ی ترافیک سیستم (نیاز به دسترسی مدیر).
- **kill switch** واقعی.
- **حذف خودکار سرورهایی که از اشتراک برداشته شده‌اند** (فعلاً فقط سرورهای تازه اضافه می‌شوند).
- **بسته‌بندی نصب‌کننده** (`tauri build`) و انتشار در Releases.
- **ساخت کانفیگ Xray** (فعلاً Xray با کانفیگ خود کاربر اجرا می‌شود).
- **DoH/DoT** در تست DNS.
- **تست‌های E2E** با tauri-driver.
